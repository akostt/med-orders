# МедЗаказ — приложение приёма заказов медицинской техники

Курсовой проект ВлГУ, колледж инновационных технологий и предпринимательства.
Руководитель: Лексин А.Ю. Исполнитель: Костин А.В., ст. гр. ИПсп-123.

## Что сейчас работает

Данные загружаются из SQL Server через EF Core.

- **Каталог** (макет 1): фильтры по категории, цене, наличию, наличию РУ и производителю, сортировка, поиск из шапки сайта, пагинация, карточки товаров с плашками остатков и РУ/СС.
- **Карточка товара с оформлением заказа** (макет 2): характеристики, гарантия, хранение, срок годности, выбор количества и способа доставки, расчёт итога (НДС из настроек). При оформлении заказ записывается в БД, а товар резервируется на складе в одной транзакции.

## Что не реализовано (пока)

Авторизация и роли, корзина, личный кабинет клиента (макет 3), панель менеджера (макет 4), документы счёт/накладная/УПД, журнал действий, отчёты, тесты, миграции, Docker-образ приложения.

Кнопка «В корзину» в каталоге ведёт сразу на карточку товара с формой оформления, потому что корзины пока нет.

## Запуск

1. Поднять SQL Server (в `.env` задан `MSSQL_SA_PASSWORD`, см. `.env.example`):
   ```bash
   docker compose up -d sqlserver
   ```
2. Указать строку подключения одним из способов:
   - переменной окружения (пароль не попадает в файлы):
     ```bash
     export ConnectionStrings__MedOrders="Server=localhost,1433;Database=MedOrders;User Id=sa;Password=<ПАРОЛЬ_SA>;TrustServerCertificate=True"
     ```
   - либо заменить `SET_VIA_ENVIRONMENT` в `src/MedOrders.Web/appsettings.Development.json` на пароль локально (файл не коммитить).
3. Запустить приложение:
   ```bash
   cd src/MedOrders.Web
   dotnet run
   ```
4. Открыть адрес, который выведет `dotnet run` (обычно `http://localhost:5xxx`).

При первом запуске в режиме Development EF Core создаёт базу `MedOrders` и заполняет её демо-данными из макетов (`EnsureCreated`).

Пересоздать базу:
```bash
docker exec sqlserver /opt/mssql-tools18/bin/sqlcmd -S localhost -U sa -P "$MSSQL_SA_PASSWORD" -C -Q "DROP DATABASE MedOrders"
```
После этого снова `dotnet run`.

## Отклонения от словаря данных (ЛР3) — нужно согласовать

- Нет таблиц `User`, `Role`, `Document`, `ActionLog`: авторизации пока нет.
- `Client` упрощён: `DisplayName` вместо ФИО, без связи с учётной записью.
- Добавлены поля: `Product.Specifications` (характеристики из макета), `Product.ShelfLifeMonths`, `Order.DiscountPercent`, `OrderItem.WarehouseId` (нужен, чтобы снимать резерв именно с того склада).
- Перечисления хранятся строкой с именем значения (например `Accepted`), а не русской подписью из словаря.
- Схема создаётся через `EnsureCreated`, а не миграциями. Для продакшена нужно перейти на `dotnet ef migrations`.

## Структура проекта

```
src/MedOrders.Web/
  Program.cs                 запуск приложения и регистрация сервисов
  Domain/                    сущности базы данных и перечисления, по одному классу на файл
    Identity/                учётные записи и роли
  Persistence/               контекст EF Core и данные для миграции
    Configurations/          схема каждой таблицы (один класс на таблицу)
    Seed/                    демо-каталог и учётные записи (HasData)
  Services/                  бизнес-логика; у каждого класса одна задача
    Orders/                  оформление заказа, расчёт итога, проверка полей заказа
    Products/                добавление товара
    Accounts/                регистрация клиента
  Security/                  роли, claim-ы, вход и тексты ошибок Identity
  Endpoints/                 HTTP-адреса входа и выхода
  Components/                страницы и общие компоненты интерфейса (Razor)
```

Правила именования: сервис — `…Service` (например `OrderService`), команда для записи данных — `…Command`, данные для показа — `…Card`, `…Details`, `…Result`, проверки полей — `…Validator`.

## Учётные записи и миграции

Учётные записи и роли хранятся в таблицах `User` и `Role` в SQL Server. Они попадают в миграцию через `HasData` (`Data/SeedAccounts.cs`), поэтому отдельный сидер и переменные `ADMIN_*` не нужны.

Первый запуск с новой схемой:

```bash
dotnet tool install --global dotnet-ef        # один раз
dotnet ef migrations add InitialCreate -p src/MedOrders.Web -s src/MedOrders.Web
docker exec sqlserver /opt/mssql-tools18/bin/sqlcmd -S localhost -U sa -P "$MSSQL_SA_PASSWORD" -C -Q "DROP DATABASE IF EXISTS MedOrders"
cd src/MedOrders.Web && dotnet run            # в Development миграции применяются при старте
```

Подключение к базе задаётся как раньше (`ConnectionStrings__MedOrders` или `appsettings.Development.json`).

| Логин | Роль | ФИО | Пароль |
|---|---|---|---|
| admin | администратор | Администратор системы | Пароль1 |
| manager | менеджер | Петров Д.С. | Пароль1 |
| ivanova | клиент | Иванова Е.С. | Пароль1 |

Демо-аккаунты используют один пароль `Пароль1`. После развёртывания пароль стоит сменить через SQL: `UPDATE [User] SET PasswordHash = N'<хеш>' WHERE Login = N'admin'`, хеш получается скриптом ниже.

### Добавление пользователя вручную

1. Получить хеш пароля:
   ```bash
   python3 tools/make_password_hash.py "Пароль1"
   ```
2. Заполнить и выполнить `tools/add_user.sql` (логин, email, ФИО, роль, хеш). Для роли «клиент» скрипт также создаёт профиль в таблице `Client`.

Роли: `клиент` (каталог и заказы), `менеджер` (каталог, добавление товара), `администратор`.

Правила пароля: не менее 8 символов, заглавные и строчные буквы, цифры. После 5 неудачных входов учётная запись блокируется на время. Блокировка: `UPDATE [User] SET IsActive = 0 WHERE Login = N'логин'`.

Регистрация клиента по ссылке «Регистрация клиента» осталась доступной. Если она не нужна, удалите `Pages/Account/Register.razor`.

## Диаграмма деятельности «Авторизация» (ЛР4) → код

| Шаг диаграммы | Где в коде |
|---|---|
| Ввести логин и пароль | `Components/Pages/Account/Login.razor` |
| Проверить хеш пароля и признак активности | `Endpoints/AccountEndpoints.cs` → `PasswordSignInAsync`; `Security/ApplicationSignInManager.cs` → `CanSignInAsync` |
| Данные неверны → сообщение об ошибке и повторный ввод | `Login.razor`, параметр `?error=invalid/blocked/locked` |
| Определить роль пользователя | `Security/ApplicationClaimsPrincipalFactory.cs` (claim `ClaimTypes.Role`) |
| Открыть интерфейс, соответствующий роли | `Routes.razor` (`AuthorizeRouteView`), атрибуты `[Authorize]` и `[Authorize(Roles = …)]` на страницах |

Диаграмма «Оформление заказа» и «Добавление товара» реализованы в этом же проекте. Подробности см. в предыдущих разделах README.
